  Field SERVER tự ghi vào bản ghi — đừng đặt tay:
    - hwid        server bind lần verify đầu (khi field đang rỗng)
    - activatedAt server ghi cùng lúc bind hwid. Server KHÔNG BAO GIỜ đọc lại nó,
                  nên không cần khai trong template. Trên RTDB `null` = XOÁ key,
                  tức là "activatedAt": null và bỏ trắng là một.

  Field vắng mặt = hành vi v1:
    - expiresAt vắng  → key VĨNH VIỄN (không hết hạn). Đây là lý do fleet cũ
                        vẫn chạy sau khi bật lifecycle.
    - graceDays vắng  → dùng LICENSE_GRACE_DAYS (mặc định 7)
    - seats vắng      → DATAHUB_DEFAULT_SEATS (mặc định 3)
    - modulePolicy vắng → server điền autoUpdate/silentUpdate/applyOnNextStartup = true
                        ⚠ ngược hẳn template (autoUpdate: false). Luôn khai đủ
                        modulePolicy, đừng dựa vào mặc định.

  ─── 5 cái bẫy đã kiểm chứng trên server hiện tại ───────────────────────

  A. expiresAt SAI CÚ PHÁP = VĨNH VIỄN, không phải lỗi.
     parseInstant() trả null cho giá trị không đọc được, và null không phân biệt
     được với "vắng mặt" → evaluateLicense cho `allowed: true` vô thời hạn. Dấu
     hiệu duy nhất là log `license.expires_at_unparseable`. Một lỗi gõ = key
     miễn phí trọn đời.
     Kèm theo: "2026-10-16" trần bị Date.parse đọc là 00:00 **UTC** = 07:00 giờ VN,
     lệch 7 tiếng so với mốc. Luôn ghi đủ offset `+07:00`, hoặc dùng dạng cũ
     `16-10-2026` (được đọc theo giờ VN).

  B. graceDays: null → cổng dùng 7 nhưng BÁO VỀ CLIENT LÀ 0.
     evaluateLicense chặn null và lấy mặc định 7; còn response builder dùng
     `Number.isFinite(Number(data.graceDays))`, và Number(null) === 0 là hữu hạn.
     Hai tầng lệch nhau. Quy tắc: thiếu field thì BỎ HẲN, không ghi null.

  C. middleCode placeholder = KHÔNG enroll được, chứ không phải enroll tự do.
     PLACEHOLDER_SITE_CODES = { "", "0000", "00000", "0", "DEFAULT", "NONE", "TBD" }.
     resolveLicenseSiteCodes() LOẠI các giá trị này; danh sách rỗng làm
     issueDataHubAssertion() trả null → DataHub từ chối enroll. Trước đây
     `filter(Boolean)` cho "0000" đi qua, dồn nhiều khách vào MỘT tenant DataHub
     và họ đọc được dữ liệu của nhau. Đây là lý do template dùng "TBD".
     Việc đăng nhập vẫn được phép trừ khi REQUIRE_UNIQUE_SITE_CODE=1 (đang tắt).

  D. siteCodes: [] TẮT enroll dù middleCode hợp lệ.
     Chuỗi fallback là `Array.isArray(siteCodes) ? siteCodes : [siteCode, siteId, middleCode]`
     — hễ siteCodes là mảng thì nó THẮNG, kể cả mảng rỗng. Không cần khách nhiều
     chi nhánh thì bỏ hẳn field, đừng để mảng rỗng.

  E. skipHashCheck: false có 3 tác dụng, và tác dụng nguy hiểm nằm ở CLIENT.
     - Server: chỉ chặn khi VALID_EXE_HASHES khác rỗng (hiện đang rỗng ⇒ vô hại).
     - Client: Program.cs bật IntegrityService (đối chiếu DLL với hash-manifest),
       VpsModuleProvider.VerifyHash (chặn nạp module DLL sai hash), và
       SmallUpdateService KHÔNG còn bỏ qua kiểm tra chữ ký.
     Nói cách khác `false` không phải "siết bảo mật miễn phí" — nó có thể chặn nạp
     module hoặc chặn small-update. Muốn đổi thì phải test kèm manifest thật.

{
  "payload":      "eyJhbGciOiJSUzI1NiIs...",      // JWT RS256, client verify bằng public key nhúng sẵn
  "sid":          "0463903a-4baf-4807-b688-...",  // session ID
  "tier":         "ULTRA",                        // giữ ở root cho client cũ
  "middleCode":   "HN01",
  "skipHashCheck": true,
  "modulePolicy": { "autoUpdate": false, "silentUpdate": true, "applyOnNextStartup": true },

  "license": {
    "status":            "active",
    "tier":              "ULTRA",
    "middleCode":        "HN01",
    "siteCode":          "HN01",                       // = middleCode, đã upper-case
    "skipHashCheck":     true,
    "modulePolicy":      { ... },
    "effectiveStatus":   "active",                     // "active" | "grace" | "expired"
    "expiresAt":         "2026-10-16T00:00:00+07:00",  // null nếu key v1
    "graceUntil":        "2026-10-23T00:00:00+07:00",  // null nếu key v1
    "daysRemaining":     53,                           // null nếu key v1
    "graceDays":         7,                            // ⚠ báo 0 nếu bản ghi ghi null — bẫy B mục 1
    "offlineGraceHours": 72,
    "billingAnchorDay":  16,
    "seats":             3
  },

  "cfg": {
    "dataSpreadsheetId": "1AbCdEfGhIjKlMnOpQrStUv...",  // "" nếu bản ghi để trống
    "updateChannel":     "stable"
  },

  "datahub": {
    "apiBaseUrl":         "https://datahub.example.com",
    "siteId":             "HN01",
    "siteCode":           "HN01",
    "licenseAssertion":   "v1rs256.<b64url payload>.<b64url sig>",  // KHÔNG phải JWT — xem dưới
    "assertionExpiresAt": 1789491600,
    "manifests":          { ... }                       // xem mục 4
  }
}

  licenseAssertion — định dạng dây thật:
    "v1rs256." + base64url(payload) + "." + base64url(RSASSA-PKCS1-v1_5 SHA-256)
    Payload là JSON PascalCase, đúng 8 claim khớp LicenseAssertionPayload.cs:
    Channel, SiteCodes, ExpiresAt, DataHubUrl, Seats, TokenVersion, Issuer, Audience.
    ⚠ System.Text.Json phân biệt hoa/thường: camelCase => payload rỗng => VPS trả 401.
    Khi không phát được (site code placeholder), server trả licenseAssertion: ""
    và assertionExpiresAt: 0 — KHÔNG phải null, và HTTP vẫn là 200.

  Mã lỗi (HTTP → error), theo đúng thứ tự cổng trong verify-license:
    404 LICENSE_NOT_FOUND           key không tồn tại
    401 LICENSE_INACTIVE            status !== "active" (so sánh nghiêm ngặt)
    403 LICENSE_EXPIRED             quá expiresAt + graceDays  (kèm expiresAt/graceUntil)
    403 LICENSE_TIER_INVALID        tier không thuộc {BASE, ULTRA}
    403 LICENSE_SITE_CODE_INVALID   middleCode là placeholder (chỉ khi REQUIRE_UNIQUE_SITE_CODE=1)
    403 HASH_INVALID                exe hash không khớp VALID_EXE_HASHES (chỉ khi biến này khác rỗng)
    401 HWID_MISMATCH               key đã bind máy khác
    503 FIREBASE_TIMEOUT            Firebase quá FIREBASE_OPERATION_TIMEOUT_MS

  Hệ quả cần biết khi đặt giá trị per-key:

    - Hạn dùng hiện chỉ được thi hành ở SERVER (403 lúc verify-license). App

  app (quyết định của owner 2026-08-24). Heartbeat không nâng/hạ tier.

┌─────────────────────────────────────────────────────────┐
│ 5. QUY TẮC EXPIRESAT — MỐC NGÀY 16                      │
│    backend/render-license-server/license-expiry.js      │
└─────────────────────────────────────────────────────────┘

  License bán theo kỳ 1 tháng nhưng luôn hết hạn 00:00 ngày 16 (Asia/Ho_Chi_Minh):

      expiresAt = mốc "ngày 16, 00:00 +07:00" SỚM NHẤT mà >= (nửa đêm ngày tạo + 30 ngày)

  Tính theo ngày tròn, không theo giờ tạo key. Ví dụ:

      createdAt            expiresAt            số ngày
      2026-08-01           2026-09-16           46
      2026-08-15           2026-09-16           32
      2026-08-16           2026-09-16           31
      2026-08-17 10:00     2026-09-16           30   ← nhờ làm tròn ngày
      2026-08-18           2026-10-16           59
      2026-08-24           2026-10-16           53
      2026-12-20           2027-02-16           58
      2019-12-01           2020-01-16           46   ← cặp sentinel trong file mẫu

  Cách sinh giá trị:
      node -e "console.log(require('./license-expiry').computeExpiry('2026-08-24').expiresAt)"
